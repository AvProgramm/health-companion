# Render + Vercel deployment preparation

Status: examples only, not deployed. Yash chose MIT for original code and confirmed Gemini Free Tier, so private diary context is blocked. Read the single interview walkthrough for feature scope. Do not introduce PostgreSQL, sync, accounts or vector storage during deployment.

1. Finish the phone checklist and keep the successful demo video. Local check/build passing is not a hosted-phone test.
2. Import the repository into Render as a Python web service using the repository root (not services/coach alone), or review/copy render.yaml.example. The service needs apps/web/src/data/exercise-index.json as well as the coach files. Python is pinned to the locally checked 3.13.9. Health /api/health proves startup, not provider quota or AI quality. Keep automatic deploys off for the interview.
3. Set provider credentials privately in Render using the same names as .env.example. Never paste them into Git or Vercel frontend variables. The agent must not open or print local secret files. No credentials are included in the examples. Empty optional provider keys mean that stage is unavailable; do not assume every sync:false field is mandatory for the diary.
4. Import the frontend into Vercel with repository root, the example install/build/output settings, and replace the reserved .invalid rewrite destination with the actual Render HTTPS hostname. Copy the reviewed example to root vercel.json only after replacing that destination. No host URL is guessed in this checkpoint. The app uses same-origin /api paths, so the Vercel external rewrite is the bridge; the Vite laptop proxy does not run on Vercel.
5. Put the exact Vercel HTTPS origin into Render COACH_ALLOWED_ORIGINS and restart/redeploy the backend. RENDER_EXTERNAL_HOSTNAME is added automatically to trusted hosts. Add exact custom hosts only if needed. Wildcards, nonlocal HTTP origins and path/query/credential URLs are rejected at startup. Origin checks are not account authentication or a rate-limit system; decide suitable public-demo access/quotas before exposing model endpoints.
6. Confirm Render memory/cold-start limits and that pinned Linux dependencies install. This has not been verified on Render. A missing local MiniLM cache means word-based retrieval; do not claim hosted fused retrieval without supplying a licensed reviewed encoder. Do not fetch weights automatically.
7. Model weights are ignored by Git. A clean hosted build therefore does not include the laptop's local photo model; the hosted reader remains available when its server key is configured. Do not upload research models/photos to work around that without reviewing their redistribution terms. The existing laptop fallback remains intact.
8. Check https://RENDER_HOST/api/health, then /api/health through Vercel. Check a generic food lookup, chat, Trainer, photo failure path and public barcode. Verify an unrelated origin is refused. Never send real diary context: it is paused. Avoid personal details in typed questions or photos on the unpaid service.
9. On phone mobile data, disconnect USB, open the Vercel URL, reload and rehearse. The hosted URL has its own browser storage: laptop-origin entries do not move automatically. If transferring a diary is wanted, use a checked export/restore consciously; do not silently upload it. Test offline reopening and preserve both copies.
10. Record deployed URLs, actual host results, provider limits, licence/third-party notices and the phone result in docs/test-log.md. A Free instance may sleep; a free database is not provisioned by these files. No billing, provisioning or publication has happened just because the templates exist.
